# CRM — среда для обучения работе с клиентами

CRM для учебной практики по работе с данными компаний. Интерфейс создан на React и TypeScript, API — на Express, данные хранятся в SQLite через Prisma ORM.

## Структура проекта

```text
CRM/
├── frontend/                    # React-интерфейс и сервер разработки Vite
│   ├── public/                  # Статические файлы
│   ├── src/
│   │   ├── assets/              # Изображения, импортируемые приложением
│   │   ├── components/          # Общие компоненты: Header, Menu, Footer
│   │   ├── features/            # Функциональные компоненты, например список клиентов
│   │   ├── lib/                 # Вспомогательный код API и авторизации
│   │   ├── pages/               # Страницы: инструкция, клиенты, вход, регистрация
│   │   │   └── routes/          # Маршруты и защита страницы клиентов
│   │   ├── styles/              # Токены, базовые стили, стили раскладки
│   │   │   └── components/      # Стили форм, списков, меню и авторизации
│   │   ├── App.tsx              # Каркас приложения и маршрутизатор
│   │   └── main.tsx             # Точка входа React-приложения
│   ├── package.json
│   └── vite.config.ts           # Проксирование /api на backend
└── backend/                     # Express API и база данных
    ├── prisma/
    │   └── schema.prisma        # Модели User и Customer
    ├── src/
    │   ├── auth.ts              # Better Auth, Prisma-адаптер и username-плагин
    │   ├── index.ts             # API-маршруты, проверка сессий, запуск сервера
    │   └── init-db.ts           # Создание admin-пользователя и тестового клиента
    ├── package.json
    └── tsconfig.json
```

## Страницы интерфейса

| Адрес | Страница | Назначение |
|---|---|---|
| `/` | Инструкция | Правила работы с учебной средой |
| `/login` | Вход | Авторизация пользователя |
| `/register` | Регистрация | Создание пользователя |
| `/asiakkaat` | Клиенты | Защищённая страница просмотра и добавления клиентов |

Изменение и удаление клиентов доступны через API, но пока не реализованы в интерфейсе.

## Технологии

- **Frontend:** React 19, TypeScript, React Router, Vite, Tailwind CSS 4
- **Backend:** Node.js, Express 5, TypeScript
- **База данных:** SQLite, Prisma ORM 6
- **Авторизация:** Better Auth с username-плагином и cookie-сессиями

## Локальный запуск

Нужны Node.js и npm. Установите зависимости отдельно для frontend и backend:

```powershell
cd backend
npm install

cd ..\frontend
npm install
```

Создайте файл `backend/.env` и задайте необходимые переменные:

```dotenv
DATABASE_URL="file:./dev.db"
BETTER_AUTH_SECRET="замените-на-длинный-уникальный-секрет"
ADMIN_PASSWORD="пароль-длиной-не-менее-8-символов"
```

`BETTER_AUTH_SECRET` — секрет Better Auth (не менее 32 символов); `ADMIN_PASSWORD` используется при первоначальном создании admin-пользователя. Не добавляйте реальные секреты в систему контроля версий. При переходе со старой схемы можно оставить `JWT_SECRET` вместо `BETTER_AUTH_SECRET`.

Новая схема авторизации хранит пользователей и сессии в отдельных таблицах Better Auth; старая таблица `User` сохраняется, но старые пароли автоматически не переносятся. Для входа старым пользователям нужно зарегистрировать аккаунт заново. Admin-аккаунт создаётся командой `db:init` из `ADMIN_PASSWORD`.

Инициализируйте базу данных из каталога `backend`:

```powershell
cd backend
npm run db:generate
npm run db:push
npm run db:init
```

Запустите backend и frontend в отдельных терминалах:

```powershell
# Терминал 1
cd backend
npm run dev
```

```powershell
# Терминал 2
cd frontend
npm run dev
```

Frontend будет доступен по адресу `http://localhost:5173`, backend — `http://localhost:3001`. Vite проксирует запросы `/api` на backend. Порт backend можно изменить переменной `PORT`.

## API

Маршруты авторизации Better Auth доступны под `/api/auth/*`. Клиент отправляет и получает HttpOnly cookie-сессию. Для маршрутов клиентов backend проверяет эту сессию; вручную задавать заголовок `Authorization` не нужно.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/auth/sign-up/email` | Регистрация пользователя через Better Auth |
| `POST` | `/api/auth/sign-in/username` | Вход по имени пользователя |
| `GET` | `/api/auth/get-session` | Получение текущей сессии |
| `POST` | `/api/auth/sign-out` | Завершение текущей сессии |
| `GET` | `/api/customers` | Получить список клиентов |
| `POST` | `/api/customers` | Добавить клиента |
| `PUT` | `/api/customers/:id` | Обновить клиента |
| `DELETE` | `/api/customers/:id` | Удалить клиента |

Поля клиента: `companyName`, `businessId`, `phone`, `billingAddress`.

## Команды

Команды frontend (запускать из `frontend/`):

| Команда | Назначение |
|---|---|
| `npm run dev` | Запустить Vite в режиме разработки |

## Предлагаемый план развития

1. **Завершить управление клиентами в интерфейсе:** добавить редактирование и удаление, подтверждение удаления.
2. **Улучшить работу со списком:** поиск, состояния загрузки и пустого списка, единая обработка ошибок.
3. **Уточнить валидацию:** проверять формат имени пользователя, пароля и бизнес-идентификатора компании; показывать ошибки рядом с полями.
4. **Добавить тесты:** покрыть API и основные пользовательские сценарии, особенно авторизацию и операции с клиентами.
5. **Подготовить к эксплуатации:** пересмотреть хранение токенов, CORS, управление секретами, логирование и резервное копирование.

Это предварительный план, основанный на текущих возможностях проекта; приоритеты можно менять.
